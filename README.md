# 정책자금 랜딩페이지 (Meta 광고용)

한국경영지원솔루션(KBSS) **정책자금** 단일 주제 랜딩페이지.
Claude Design 캔버스(`KBSS 홈페이지.dc.html`)를 **의존성 없는 정적 HTML**로 1:1 재현했습니다.

```
index.html              단일 파일 랜딩페이지 (CSS·JS 인라인)
assets/hero-handshake.jpg   히어로 우측 이미지
assets/consulting.jpg       진행절차 옆 상담 사진
```

빌드·서버·프레임워크가 필요 없습니다. 폴더째 올리면 끝입니다.

---

## 1. 원본 캔버스와의 관계

원본은 React 런타임(`support.js` + unpkg React) 위에서 도는 디자인 캔버스라 그대로는 배포할 수 없습니다.
이 저장소는 캔버스가 참조하던 디자인시스템 소스를 그대로 옮겨 순수 CSS로 재작성한 것입니다.

| 원본 | 재현 방식 |
|---|---|
| `_ds/tokens/*.css` (colors·typography·spacing·fonts) | `:root` 커스텀 프로퍼티로 **값 그대로** 이식 |
| `Badge` / `Button` / `Card` / `ProcessStep` / `SectionHeader` / `StatCounter` (JSX) | `.ds-badge` / `.ds-btn` / `.ds-card` / `.ds-step` / `.ds-sh` / `.ds-stat` CSS 클래스 |
| `<x-import>` 컴포넌트 인스턴스 | 해당 클래스를 적용한 정적 마크업 |
| `DCLogic` 상태 로직 (`scrollToApply`, 카운트업, `handleApplySubmit`) | 바닐라 JS로 동일 동작 (수치·이징·threshold 동일) |
| `<sc-if value="{{ applySubmitted }}">` 분기 | `hidden` 속성 토글 |
| unpkg React / Claude Design 런타임 | **제거** (외부 JS 의존 없음) |

컴포넌트 55개 선택자의 computed style을 원본 JSX 스타일 객체와 대조해 전부 일치하는 것을 확인했습니다.

### 재현한 동작
- 히어로 골드 버튼 → `#apply`로 smooth 스크롤
- 실적 카운터 → `#stats-2` 진입 시(threshold 0.4) 1400ms, `1-(1-p)³` 이징, `ko-KR` 천단위 콤마 — 목표값 `[3799, 630, 10]`
- 자금 카드 6종의 펄스 도트 (`pulseDot 1.6s`, 0.2초씩 지연)
- 신청서 제출 → 폼이 "신청이 접수되었습니다" 패널로 교체
- 760px 이하 하단 고정 CTA 바

### 추가한 것 (디자인 변경 없음)
- **리드 전송 파이프라인** — 원본 폼은 화면만 바뀌고 데이터가 어디로도 가지 않습니다. 실제 수집이 되도록 아래 2번을 붙였습니다.
- Meta 픽셀 + `Lead` 전환 이벤트, UTM·fbclid 자동 수집
- 휴대전화 하이픈 자동 입력 및 형식 검증, 필수값 검증, 허니팟 스팸 차단
- **모바일 반응형 보정** — 원본 캔버스는 1440px 데스크톱 기준으로만 설계되어 모바일에서 3열 그리드와 48px 제목이 화면을 넘칩니다. CSS 맨 아래 주석으로 구분된 `@media` 블록이며, 완전히 동일하게 두려면 그 블록만 지우면 됩니다.

## 2. 신청 데이터 → 구글 시트 (무료, 5분)

접수용 시트는 이미 만들어져 있습니다.

**시트 :** [KBSS 정책자금 상담신청 접수](https://docs.google.com/spreadsheets/d/1z5DyvfjIzvOrDvaulnC8-ZhqJ7MNqxHI4p_v1Hf2Wno/edit)

### 단계

**① 시트에서 Apps Script 열기**
위 시트를 열고 상단 메뉴 **확장 프로그램 → Apps Script**

**② 코드 붙여넣기**
편집기에 있던 `function myFunction() {}` 을 모두 지우고,
이 저장소의 [`apps-script/Code.gs`](apps-script/Code.gs) 전체를 붙여넣습니다.
맨 위 `NOTIFY_EMAIL` 을 알림 받을 주소로 바꾸세요 (알림이 필요 없으면 `''` 로 비웁니다).
저장 (Ctrl+S).

**③ 권한 승인 + 동작 확인**
편집기 상단 함수 선택 상자에서 **`테스트`** 를 고르고 **▶ 실행**.
- "이 앱은 Google에서 확인하지 않았습니다" 경고가 뜨면 → **고급 → (안전하지 않음) 이동**
  직접 만든 스크립트라 정상입니다.
- 승인 후 시트로 돌아가면 헤더 서식이 잡히고 **테스트 행 1건**이 들어와 있습니다.
- 정리는 `테스트행삭제` 함수를 실행하면 됩니다.

**④ 웹 앱으로 배포**
**배포 → 새 배포 → 톱니바퀴 → 웹 앱** 선택 후

| 항목 | 값 |
|---|---|
| 설명 | (아무거나) |
| 실행 계정 | **나** |
| 액세스 권한 | **모든 사용자** ← 이게 핵심입니다 |

**배포** 를 누르면 `https://script.google.com/macros/s/......../exec` 주소가 나옵니다. 복사하세요.

> ⚠️ 액세스 권한이 "나만"이면 랜딩페이지에서 전송이 실패합니다. 반드시 **모든 사용자**.

**⑤ 배포 확인**
복사한 주소를 브라우저 주소창에 그대로 붙여넣어 엽니다.
`KBSS 접수 엔드포인트 정상 동작 중 · 2026-…` 이 보이면 성공입니다.

**⑥ 랜딩페이지에 연결**
`index.html` 맨 아래 `CONFIG` 의 `ENDPOINT` 에 붙여넣습니다.

```js
var CONFIG = {
  ENDPOINT   : "https://script.google.com/macros/s/........./exec",
  PIXEL_ID   : "",
  LEAD_EVENT : "Lead"
};
```

**⑦ 실제 제출 테스트**
페이지를 열어 신청서를 한 번 제출하고, 시트에 행이 들어오는지 확인하세요.
`ENDPOINT` 가 비어 있으면 전송 없이 완료 화면만 뜨는 **테스트 모드**로 동작합니다.

### 연결이 되는지 바로 확인하려면

`tools/연결테스트.html` 을 내려받아 브라우저로 열고 웹 앱 URL 을 붙여넣으면
① 배포 확인 ② 실제 테스트 신청 전송 을 눌러 결과를 바로 볼 수 있습니다.
성공하면 `index.html` 에 붙여넣을 `CONFIG` 줄까지 만들어 줍니다.
실패하면 원인(액세스 권한 / 스크립트 오류 / 주소 형식)을 구분해 해결 방법을 알려 줍니다.

> ⚠️ 스프레드시트 주소(`docs.google.com/spreadsheets/...`)는 연동에 쓸 수 없습니다.
> 폼이 데이터를 보내는 곳은 Apps Script 를 웹 앱으로 배포했을 때 나오는
> `script.google.com/macros/s/.../exec` 주소입니다.

### 터미널에서 확인하려면

```bash
curl -L -X POST "붙여넣은_웹앱_URL" \
  -H "Content-Type: text/plain" \
  -d '{"name":"curl테스트","phone":"010-1111-2222","company":"(주)확인","agree_privacy":"Y"}'
```

`ok` 가 돌아오고 시트에 행이 추가되면 정상입니다.

### 시트 구성

| 열 | 내용 |
|---|---|
| 접수일시 | 한국 시간 자동 기록 |
| 상태 | 드롭다운 — 신규 / 연락함 / 상담중 / 진행 / 보류 / 종결 |
| 성함 · 휴대전화 · 기업명 · 업력 · 소재지 · 업종 · 매출 · 상담시간 | 신청서 입력값 |
| 개인정보 동의 | 동의 여부 |
| 유입 매체 · 캠페인 · 광고 소재 · fbclid · 유입 경로 | 어느 광고에서 온 리드인지 자동 기록 |
| 메모 | 직접 작성. 같은 번호로 다시 신청하면 `⚠ 중복 접수` 자동 표시 + 행 배경색 |

1행 고정, 휴대전화 열까지 틀 고정, 필터가 미리 걸려 있습니다.
오류가 나면 `_오류로그` 탭이 자동 생성되어 원인이 기록됩니다.

### 스크립트를 고친 뒤에는

Apps Script 에서 **배포 → 배포 관리 → 연필 아이콘 → 버전 [새 버전] → 배포** 를 눌러야
변경이 반영됩니다. URL 은 그대로 유지됩니다. ("새 배포"를 다시 만들면 URL이 바뀝니다.)

### 자주 막히는 지점

| 증상 | 원인 / 해결 |
|---|---|
| 제출 시 "전송 중 문제가 발생했습니다" | 배포 액세스 권한이 "나만" → **모든 사용자** 로 다시 배포 |
| 웹앱 URL 을 열면 로그인 화면 | 같은 원인 |
| 시트에 행이 안 들어옴 | `테스트` 함수를 실행해 권한 승인을 마쳤는지 확인 |
| 알림 메일이 안 옴 | `NOTIFY_EMAIL` 오타 / Gmail 일일 발송 한도(무료 100통) 초과 |
| 코드를 고쳤는데 그대로 | **배포 관리**에서 새 버전으로 갱신하지 않음 |

## 3. Meta 광고 세팅

- [ ] **픽셀 확인** — Chrome 확장 *Meta Pixel Helper*로 `PageView` 수신 확인
- [ ] **전환 이벤트** — 이벤트 관리자에서 `Lead`를 전환으로 등록, 캠페인 목표는 **잠재 고객(리드)**
- [ ] **도메인 인증** — 비즈니스 설정 → 브랜드 가치 보호 → 도메인
- [ ] **UTM** — 광고 URL 매개변수에 넣으면 시트에 자동 기록됩니다
  ```
  utm_source=facebook&utm_medium=paid&utm_campaign={{campaign.name}}&utm_content={{ad.name}}
  ```

### 심사 반려를 피하려면
- ❌ "100% 승인", "무조건 지원" 등 **보장 표현 금지**
- ❌ 금리·한도 확정 제시 금지 (본 페이지는 "기관 심사로 결정" 기조로 작성)
- ❌ 대출 알선·중개 오인 표현 금지 (유의사항 1항에 컨설팅업임을 명시)
- ✅ 개인정보 수집·이용 동의 체크는 필수 항목으로 포함

## 5. 자주 수정하는 부분

| 무엇을 | 어디를 |
|---|---|
| 실적 숫자 | `<script>` 안 `statTargets = [3799, 630, 10]` |
| 헤드라인 | `.hero__title` (`<mark>`으로 감싼 부분이 골드 강조) |
| 브랜드 색 | `:root`의 `--color-primary`(네이비) / `--color-accent-gold`(골드) / `--color-secondary`(딥네이비) |
| 자금 카드 | `.fundgrid` 안 `.fundcell` 6개, 배경 틴트는 `.fundcell--N`의 `--surface` |
| 폼 항목 | `#applyForm`. 필수 항목은 `data-req`(입력) / `data-req-check`(체크박스) 속성으로 표시됩니다 |
| 이미지 | `assets/` 교체 (히어로는 가로로 넓은 사진, 상담 사진은 4:3 권장) |

### 이미지 해상도
원본 캔버스에서 받은 사진이 `540×358`, `314×215`로 작습니다. 히어로는 실제로 약 550×600px 영역에 채워지므로
**1200px 이상** 원본으로 교체하시면 선명해집니다.
